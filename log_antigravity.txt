## 🗂️ Stack Técnica

| Item | Tecnologia |
|------|-----------|
| Framework | React 19 + Vite 8 + TypeScript 6 |
| Estilização | Vanilla CSS (`src/index.css`) com CSS variables |
| Banco de Dados | **Supabase** (PostgreSQL) |
| Cliente Supabase | `@supabase/supabase-js` v2 |
| Gráficos | `chart.js` + `react-chartjs-2` (Doughnut, Bar) |
| Ícones | `lucide-react` |
| Persistência local | `localStorage` como fallback offline |

> ⚠️ **AÇÃO NECESSÁRIA**: Se o badge do header mostrar "Local (Offline)", significa que as tabelas **ainda não foram criadas** no Supabase.  
> Acesse o painel do Supabase → SQL Editor → cole o conteúdo de `supabase_schema.sql` → Run.

### Por que aparece "Local (Offline)"?
A detecção de conectividade foi corrigida em `FinanceContext.tsx`:
- **Antes**: `supabaseConnected = true` apenas se a tabela retornasse DADOS.
- **Depois**: `supabaseConnected = true` se a QUERY não retornar ERRO (tabelas existentes mas vazias também são válidas).

### Sessão 3 — Sync Cross-Device, Responsividade Mobile, Lógica Programados
> Commit: `9b0cdf2` | Data: 2026-08-13

#### 🔵 Persistência Cross-Device (`src/context/FinanceContext.tsx`)
- **Bug raiz corrigido**: o código anterior gerava IDs temporários (`tx-1234567`) e descartava o UUID real do Supabase após insert. Agora usa `.select().single()` para capturar o UUID real e substituir o estado local → IDs sempre são UUIDs do Supabase
- **Realtime subscriptions** adicionadas para `transactions` e `scheduled_transactions`: mudanças de qualquer dispositivo propagam automaticamente para os outros via `postgres_changes`
- **Carga inicial**: removida condição `if (length > 0)` — Supabase agora é sempre a fonte de verdade ao conectar, mesmo quando retorna array vazio
- Todas as funções CRUD convertidas para `useCallback` (evita re-renders desnecessários)
- ⚠️ **Para Realtime funcionar**: habilitar em Supabase Dashboard → Database → Replication → Source → marcar `transactions` e `scheduled_transactions`

#### 🟠 Responsividade Mobile
- **`src/components/Header.tsx`**: dropdown de reset usa `position: fixed` com `z-index: 500` em mobile; posição vertical calculada dinamicamente via `getBoundingClientRect()` no botão → não sobrepõe mais os cards da página
- **`src/components/Dashboard/ExpenseDonutChart.tsx`**: `ResizeObserver` detecta container < 520px; em mobile, legenda vai para **baixo** (não à direita, que causava corte de texto); texto "TOTAL GASTOS" exibido abaixo do gráfico em mobile (não mais com `left: 35%` fixo quebrado)
- **`src/index.css`**: `.reset-dropdown-menu` usa `position: fixed` + `z-index: 500` em mobile, volta para `absolute` em ≥640px; `.app-container` recebe `overflow-x: hidden`; `.app-header` recebe `position: relative; z-index: 10`; `.dashboard-grid .glass-card` recebe `min-height: 200px` em mobile

#### 🟡 Lógica da Aba "Programados" (`src/components/Scheduled/ScheduledView.tsx` + `FinanceContext.tsx`)
- **Comportamento correto ao efetivar**:
  - `once` → **deleta** o agendamento (some de Programados, aparece em Entradas/Saídas como Pago)
  - `monthly` → avança `due_date` +1 mês (continua na lista com próxima data)
  - `weekly` → avança `due_date` +7 dias
  - `yearly` → avança `due_date` +1 ano
- **View filtrada** para mostrar apenas `is_active: true`
- **Badge de status dinâmico** por vencimento: 🔴 "Vencido há Xd" / 🟡 "Vence hoje/em Xd (≤7d)" / ⚫ "Vence em Xd"
- Contador no topo: nº ativos, nº vencidos, soma das saídas a vencer
- Confirmação de efetivação informa o que vai acontecer ("será removido" ou "data será avançada")

### Sessão 13 — Upgrade Multimodal de Áudio com Google Gemini 3.6 Flash & MediaRecorder (Antigravity)
> Data: 2026-08-28

#### 🎙️ Gravação Multimodal no Frontend (`VoiceTransactionModal.tsx`)

- Conversão automática dos chunks de áudio em Base64 e envio seguro para o backend via requisição POST.
- Exibição de estado de processamento dinâmico ("Processando com Gemini 3.6 Flash...").
- Notificação de sucesso com o badge **"Lançamento Registrado!"**, discriminação de tipo (Receita/Despesa), valor em reais, descrição resumida e categoria associada.

#### 🧠 Backend & Integração com SDK Oficial do Google GenAI (`api/voice-transaction.ts`)
- Adicionada a dependência oficial **`@google/genai`**.
- Criação do endpoint `/api/voice-transaction` (compatível com Serverless e Vercel).
- **Sanitização de Base64 e MIME Type**: Isolamento estrito dos dados Base64 com `.split(',')[1]` e extração limpa do `mimeType` (`audio/webm`, `audio/mp4`, etc., sem sufixos de codecs como `;codecs=opus`), garantindo payload 100% em conformidade com a especificação `inlineData` do SDK Google GenAI.
- Integração direta com o modelo **`gemini-3.6-flash`** utilizando a System Instruction solicitada:
  > *"Você é um extrator de dados financeiros. Ouça o áudio e devolva EXATAMENTE um objeto JSON com as seguintes chaves: "tipo" (receita ou despesa), "valor" (apenas números float), "categoria" (ex: Alimentação, Transporte, etc) e "descricao" (resumo curto). Ignore gírias e ruídos."*
- Formatação estrita com `responseMimeType: "application/json"`.
- Persistência automática no banco de dados **Supabase** (tabela `transactions`) com mapeamento inteligente da categoria do usuário autenticado.
- Suporte a Middleware local em desenvolvimento via `vite.config.ts` (`apiDevPlugin`).

  - O iOS agora aplica sua máscara squircle nativa sobre a imagem inteiriça, resultando em um atalho idêntico ao do desktop PWA: contínuo, escuro e sem qualquer fresta branca.

### ⚠️ Sessão 20 — Incidente de Segurança: Credenciais Expostas no GitHub e Rollback (Antigravity)
> Data: 2026-09-18

#### 🔴 O Incidente

**O que aconteceu:**
- O arquivo `log_antigravity.txt` continha as credenciais do Supabase hardcoded (URL e `anon_key`) nas seções de documentação.
- O arquivo foi commitado e publicado no GitHub via `git push`, expondo as chaves publicamente.
- Além disso, `src/lib/supabase.ts` possuía as credenciais como fallback hardcoded no código-fonte, também presentes no repositório.

**Credenciais expostas:**
```
VITE_SUPABASE_URL=https://hrqkxaakcknqzeauilyt.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_jYnKZTpuHCPE0U5wmVP3Og_Nsl6_CvA
```

> ℹ️ **Nota**: A `anon_key` do Supabase é uma chave **pública por design** (prefixo `sb_publishable_`). Ela não concede acesso administrativo e é protegida pelas políticas de Row Level Security (RLS) configuradas no banco. O risco real é limitado a ataques de volume (DDoS via API) ou enumeração de dados se o RLS estiver mal configurado.

---

#### 🔧 O Que Foi Tentado (e Por Que Falhou)

**Commit `9d71fa3`** — `security: remove credentials from code, untrack log_antigravity and add to .gitignore`

As seguintes ações foram executadas:
1. **`.gitignore` atualizado** para incluir `log_antigravity.txt` e `.env.local`.
2. **`git rm --cached log_antigravity.txt`** — removeu o arquivo do rastreamento do Git (mas manteve o arquivo local).
3. **`src/lib/supabase.ts` atualizado** — removidos os fallbacks hardcoded, passando a exigir exclusivamente as variáveis de ambiente `VITE_*` sem valor padrão.
4. **`git push`** para o GitHub com essas alterações.

**Por que o app foi ao ar como "Not Found":**
- Na plataforma de hospedagem (Vercel/Netlify), as variáveis de ambiente `VITE_SUPABASE_URL` e `VITE_SUPABASE_ANON_KEY` **não estavam configuradas** no painel da plataforma.
- Com os fallbacks removidos do código, `supabaseUrl` e `supabaseAnonKey` passaram a ser `undefined`.
- `createClient(undefined, undefined)` lança exceção na inicialização do módulo → o bundle quebra → a aplicação retorna 404/Not Found.

---

#### ↩️ Rollback

**Commit `f91311f`** — `Revert "security: remove credentials from code, untrack log_antigravity and add to .gitignore"`

O revert restaurou:
- `log_antigravity.txt` de volta ao repositório
- `src/lib/supabase.ts` com os fallbacks hardcoded
- `.gitignore` sem as entradas de segurança

O app voltou ao estado funcional anterior.

#### 📋 Guia: Como Fazer Corretamente (Para Futuras Migrações de Hospedagem)

Se no futuro for decidido mudar a hospedagem (Vercel → Netlify, Railway, Cloudflare Pages, etc.) ou limpar o histórico do repositório, seguir este roteiro:

**Passo 1 — Configurar variáveis de ambiente na NOVA plataforma ANTES de alterar o código:**
```
VITE_SUPABASE_URL=https://hrqkxaakcknqzeauilyt.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_jYnKZTpuHCPE0U5wmVP3Og_Nsl6_CvA
GEMINI_API_KEY=<sua chave>
```
> ⚠️ Verificar que o build na plataforma lê as variáveis `VITE_*` corretamente antes de prosseguir.

**Passo 2 — Remover os fallbacks do `src/lib/supabase.ts`:**
```ts
// ANTES (inseguro):
const supabaseUrl = import.meta.env.VITE_SUPABASE_URL || 'https://...supabase.co';

// DEPOIS (seguro):
const supabaseUrl = import.meta.env.VITE_SUPABASE_URL;
if (!supabaseUrl) throw new Error('VITE_SUPABASE_URL não configurada');
```

**Passo 3 — Adicionar ao `.gitignore`:**
```
.env.local
.env
log_antigravity.txt
```

**Passo 4 — Remover do rastreamento sem deletar o arquivo local:**
```bash
git rm --cached log_antigravity.txt
git rm --cached .env.local   # se estiver rastreado
git add .gitignore
git commit -m "security: untrack sensitive files and add to .gitignore"
```

**Passo 5 — Verificar o deploy** na plataforma nova antes de fazer `git push`.

**Passo 6 (Opcional — Limpar histórico):** Se quiser apagar as credenciais dos commits anteriores:
```bash
# Reescreve o histórico removendo o arquivo de todos os commits passados
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch log_antigravity.txt" \
  --prune-empty --tag-name-filter cat -- --all

# OU usando a ferramenta mais moderna:
npx @github-actions/git-filter-repo --path log_antigravity.txt --invert-paths
git push origin --force --all
```
> ⚠️ `git push --force` reescreve o histórico remoto. Coordenar com todos os colaboradores antes.

**Passo 7 — Revogar e regenerar credenciais comprometidas** (boa prática após qualquer exposição):
- Supabase: `Settings → API → Regenerate anon key`
- Google AI Studio: revogar e gerar nova `GEMINI_API_KEY`
